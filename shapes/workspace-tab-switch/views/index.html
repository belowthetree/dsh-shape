中间放大的卡片就是要落到的位置；标题栏里的「切换 / 当前」小标签、上方的大标题与「→ 前进 1 个」共同说明落点。列表超过五个时，两端用 ⋯ 表示还有别的工作区。

操作

  • CtrlTab 按住 Ctrl、连按 Tab 依次向后走；松开 Ctrl 落到高亮的工作区
  • CtrlShiftTab 反向（向前）走
  • ←→ 面板打开期间直接移动高亮
  • Enter 立刻切换，不用等松手
  • Esc 取消，留在原地
  • 点击卡片 直接跳到那一个工作区（任意距离）

浏览器标签页会把 Ctrl+Tab 留给它自己的标签栏，事件根本到不了页面 —— 这不是本 shape 的问题，任何网页都收不到它。 所以在浏览器里用下面这组：按住 Ctrl+Alt 连按方向键，松手同样即切换；桌面 App 窗口里 Ctrl+Tab 可用。

  • CtrlAlt→ 下一个工作区（浏览器可用）
  • CtrlAlt← 上一个工作区（浏览器可用）
  • 会话头部「⇥ 切换」 鼠标入口；头部没渲染时自动出现在右下角

说明

  • 快捷键来源 两层：dsh-shape#shortcuts 把 Ctrl+Tab / Ctrl+Shift+Tab 注册成真正的 DSH 命令（带 regions: ['page','editable']，输入框聚焦时也生效；可在设置里改键）， 另有一层 document 捕获监听负责同一组按键以及 Ctrl+Alt+方向键。 两层对同一次按键都覆盖时由去重逻辑合并，不会连跳两格。
  • 为什么还要监听 Web 宿主只接受多修饰键组合为命令默认值，单修饰键的 Ctrl+Tab 会被拒（命令仍存在，可改键绑定）；单修饰键要真正生效只能走页面级监听。
  • 切换效果 面板淡入；高亮卡上浮放大并带上该工作区的配色；翻动时卡片内容沿方向轻微位移；落点时一道白闪盖过面板，随后在顶部显示「已切换到「…」」，失败则显示橙色提示。
  • 跨距离跳转 相邻一步走 workspace.next()（顺带展开侧栏分组）；更远的卡片直接 openWorkspace(id) 打开，不会经过中间工作区。
  • 自检 控制台里能看到 [workspace-tab-switch] 已激活、命令已注册：Ctrl+Tab 以及 shortcuts.list() 回报的 keys / issue —— 若 keys 为空或带 issue，说明是该宿主没有绑定这个默认值。
  • 主题 面板按当前界面深浅自动选择配色（读取页面背景/文字亮度），不依赖额外能力。
